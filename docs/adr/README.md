# Architecture Decision Records

This directory records the significant architectural decisions made on Atlas, using the [MADR](https://adr.github.io/madr/)-influenced format described in [`template.md`](template.md).

An ADR captures a decision, the context that forced it, the options considered, and the consequences accepted. ADRs are immutable once accepted: if a decision changes, a new ADR supersedes the old one rather than editing it.

| [0137](0137-conditional-events.md) | Conditional events — a catch/boundary/event-subprocess-start that fires when a **boolean FEEL condition over process variables becomes true** (data-triggered, not message/timer/signal). The condition compiles to FEEL at deploy (a gateway condition) and is re-evaluated when a variable it reads changes: every committed write funnels through `AppendVariableEvent`, which marks the instance dirty and schedules a transient command-path `ConditionRecheck` follow-up that fires armed conditionals now true — reusing the inert-armed-catch + `AppendElementCommand(IntentCompleting)` pattern from ADR-0089/0125. Interrupting/catch fire once; non-interrupting fires once per arm (repeatable false→true edge-triggering deferred). No subscription; catches external `SetVariables`. Chosen over polling and completion-checkpoint evaluation | Accepted |
| [0138](0138-process-documentation-export.md) | Process documentation export — a BPMN process is published as one structured PDF (the diagram plus every element's `documentation` text and attached `textAnnotation` notes) so auditors, sign-off owners, and new joiners can read a process without an Atlas login. The document is **rendered in the browser**, where bpmn-js already holds the authoritative picture, and the server only validates and stores the bytes — chosen over a headless Chromium or a pure-Go re-renderer because those re-derive the diagram and would drift from the Modeler silently, each at the price of a permanent server-side dependency the single-binary posture (ADR-0124/0134) refuses. Written by a small dependency-free PDF writer shipped with the web UI rather than a vendored library, with the diagram embedded as a `DCTDecode` JPEG. A version is an immutable record with a **per-processId counter** (the ADR-0128 layering above ADR-0019 deployment versions), a JSON sidecar plus the PDF beside it under the ADR-0019/0021 atomic-write discipline, snapshotting by value what it documented; the counter rebuilds from the records at startup. Sharing is per-version, off by default, via ADR-0029's revocable opaque token at `/public/process-docs/{token}`. Design-time only — no value type, event, or recovery path | Accepted |
